# Profile 切换故障处理

## 适用范围

本文用于排查 Hermes WebUI 中配置档下拉框无法展开、点击配置档后仍停留在
`default`，或切换请求超过浏览器超时的问题。适用于多 Profile 部署。

本文不要求查看或粘贴密码、Cookie、API Key、完整 `.env` 文件或用户会话数据。

## 现象

可能出现以下一个或多个症状：

1. Composer 底部的 Profile 菜单显示 `default`，但点击其他配置档没有生效。
2. 浏览器 Network 中 `POST /api/profile/switch` 长时间 Pending，随后 UI 回退到原
   配置档或显示请求超时。
3. 下拉内容存在，但不在页面上可见或不可点击。
4. Profile 菜单混入“修改密码”和“退出登录”等账号操作，干扰配置档切换。

## 根因

本次问题由两个独立缺陷叠加造成：

1. Profile 切换接口在返回时重新构建完整 Profile 列表，并清除已预热的技能统计
   缓存。多 Profile 或技能数量较多时，会重复扫描每个 `SKILL.md`，使
   `/api/profile/switch` 超过前端请求超时。
2. 看板创建弹窗缺少一个闭合 `div`。浏览器会将后续的 `#profileDropdown` 解析为
   隐藏看板弹窗的子元素，导致菜单即使带有 `open` 样式也没有可见尺寸，点击不会
   触发配置档切换请求。

另外，Profile 选择器承担的是上下文切换职责，不应混入账号管理命令。

## 修复内容

1. 浏览器调用 `/api/profile/switch` 时使用 `include_profiles=False`，只返回新
   配置档所需的默认模型、provider、workspace 和 active 状态。
2. 普通切换不再清空按 Profile 目录缓存的技能统计；浏览器 `/api/profiles`
   控制面请求会跳过冷缓存的技能解析，避免等待可选的技能计数。
3. Profile 列表路径使用 WebUI 已解析的 Hermes 根目录，支持自定义部署目录。
4. 修复看板弹窗的 HTML 闭合结构，确保 `#profileDropdown` 位于 document body。
5. 从 Profile 下拉框移除“修改密码”和“退出登录”；账号操作保留在账号菜单和设置页。

## 线上排查步骤

### 1. 确认 WebUI 服务可用

```bash
curl -fsS http://127.0.0.1:<port>/health
```

先解决端口未监听、健康检查失败或登录失效问题，再继续 Profile 排查。

### 2. 检查 Profile 列表接口

使用已登录浏览器打开开发者工具 Network，确认：

- `GET /api/profiles` 返回多个可见 Profile；
- Composer Profile 菜单可以展开；
- 菜单中只保留 Profile 条目和“管理配置档”。

不要在终端中复制浏览器 Cookie，也不要把带身份信息的请求头写入工单。

### 3. 检查切换请求

在浏览器中选择一个非当前 Profile，观察：

- `POST /api/profile/switch` 返回 `200`；
- 响应中的 `active` 与目标 Profile 一致；
- Composer Profile 标签更新为目标名称；
- 请求不会接近前端默认的 30 秒超时边界。

服务端日志可通过受管启动方式查看：

```bash
./ctl.sh logs --lines 100
```

若日志中没有 `POST /api/profile/switch`，优先检查浏览器控制台错误以及
`#profileDropdown` 是否被隐藏容器裁剪。若请求超过数秒且日志显示 Profile/skills
扫描，确认服务已部署包含本修复的版本。

### 4. 检查 HTML 结构

在浏览器 Console 执行以下只读检查：

```javascript
document.getElementById('profileDropdown')?.parentElement === document.body
```

结果应为 `true`。若为 `false`，说明浏览器仍加载旧静态页面或发布包中存在未闭合的
弹窗标签；清理旧缓存后重新发布并重启 WebUI。

## 验收标准

1. 桌面和窄屏布局中，下拉框均可见、未超出视口、可点击。
2. `default -> deployer -> default` 等切换会更新 Composer 标签。
3. 切换接口不重新返回完整 `profiles` 列表；冷启动的选择器请求不等待全量技能扫描。
4. Profile 下拉框不显示密码修改或退出登录操作。
5. Profile 相关自动化测试通过。

## 回滚与恢复

若发布后出现无法加载静态资源或 Profile 菜单为空：

1. 使用版本控制回退本次提交，不要手工删除 Hermes Profile 或 WebUI 状态目录。
2. 重启受管 WebUI 服务。
3. 先验证 `/health`，再重新登录并检查 `/api/profiles`。

回滚只恢复应用代码；不需要修改用户密码、会话、技能目录或 Profile 配置。
