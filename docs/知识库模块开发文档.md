# 知识库模块开发文档

本文档说明 Hermes WebUI 知识库模块的功能、使用方式、接口约定和后续开发注意事项。当前版本是文件系统直连的 MVP：WebUI 直接读写一个 Obsidian 兼容的 Markdown vault，不依赖 Obsidian Electron 或 Obsidian Local REST API。

## 功能列表

- 知识库入口：在 WebUI 左侧导航中新增 Knowledge 面板。
- 目录树浏览：左侧以目录树展示 vault 内的 Markdown 文件和目录。
- 笔记查看：点击笔记后在中间详情区渲染 Markdown 内容。
- 笔记新建：支持填写标题、目录和正文，自动生成 Markdown 文件。
- 笔记编辑：支持修改已有笔记正文。
- 笔记删除：支持删除单篇 Markdown 笔记，删除前弹出确认。
- 笔记上传：支持上传 Markdown 文件到当前选中目录。
- 笔记下载：支持将当前笔记作为 Markdown 文件下载。
- 全文搜索：按标题和正文搜索 Markdown 笔记，左侧显示匹配结果和摘要。
- 标题导航：阅读和编辑模式下根据 H1~H6 生成右侧目录，支持快速跳转。
- 图片插入：编辑模式支持上传或粘贴图片，保存到 vault 附件目录并插入 Markdown 图片语法。
- Office 导入：支持通过可选 `markitdown` 适配器导入 `.docx`、`.xlsx`、`.pptx` 为 Markdown。
- 批量导入：支持上传 ZIP，批量导入其中的 Markdown 和 Office 文件，并返回逐文件失败明细。
- 附件归档：ZIP 内 Markdown 本地图片、Office 内嵌图片会保存到 `_attachments/<note-stem>/` 并写回相对链接。
- 目录管理：支持目录新建、重命名和删除，支持多级目录嵌套。
- 未保存保护：编辑或新建状态下切换笔记、刷新列表或离开 Knowledge 面板时提示确认。
- 状态记忆：前端保存目录展开状态和最近打开笔记。

## 模块架构

后端主入口在 `api/obsidian_notes.py`，负责 vault 路径解析、文件系统读写、搜索、上传下载和错误转换。批量导入相关的 ZIP 读取、Markdown 图片引用解析、Office 媒体提取和失败聚合拆分在 `api/notes_import/` 下，`api/routes.py` 只做轻量路由分发，`server.py` 增加 `PUT` 写入方法支持。

前端实现集中在 `static/obsidian_notes.js`，并在以下文件中接入 WebUI 外壳：

- `static/index.html`：新增 Knowledge 导航按钮、主面板和脚本引用。
- `static/panels.js`：接入面板切换、首次加载和未保存内容确认。
- `static/style.css`：新增目录树、详情区、搜索结果和编辑表单样式。

测试覆盖在 `tests/test_obsidian_notes_api.py`，包括后端 CRUD、默认 vault 路径、下载响应、路由分发和前端静态接入检查。

## Vault 路径配置

知识库 vault 根目录按以下优先级确定：

1. 如果设置了 `HERMES_OBSIDIAN_VAULT_DIR`，使用该环境变量指向的目录。
2. 否则使用 Hermes WebUI 的全局工作区路径加 `/obsidian`，即 `api.config.DEFAULT_WORKSPACE / "obsidian"`。

示例：

```bash
export HERMES_OBSIDIAN_VAULT_DIR=/path/to/my/obsidian-vault
python server.py
```

如果没有设置环境变量，且当前全局工作区是 `/workspace`，默认 vault 路径为：

```text
/workspace/obsidian
```

新建笔记或上传笔记时会按需创建 vault 根目录和目标目录。读取、搜索和列树时，如果 vault 目录还不存在，会返回空列表，不会报错。

## 前端使用说明

打开 WebUI 后，点击左侧导航的 Knowledge 图标进入知识库面板。

常用流程：

1. 查看笔记：在左侧目录树中点击 Markdown 笔记，右侧详情区会渲染内容。
2. 新建笔记：点击 `New`，填写标题、目录和正文后保存。
3. 编辑笔记：打开笔记后点击 `Edit`，修改正文后保存。
4. 删除笔记：打开笔记后点击 `Delete`，确认后删除当前文件。
5. 管理目录：点击目录行的操作按钮可新建子目录、重命名目录或删除目录。
6. 插入图片：编辑模式点击 `图片` 或直接粘贴图片，系统会上传附件并插入 `![](relative-path)`。
7. 上传笔记：点击 `Upload`，选择本地 `.md` 或 `.markdown` 文件，文件会上传到当前选中目录。
8. 导入 Office：点击 `Import Office`，选择 `.docx`、`.xlsx` 或 `.pptx` 文件导入为 Markdown。
9. 批量导入：点击 `批量导入 ZIP`，选择包含 Markdown、Office 和本地图片资源的 ZIP 包。
10. 下载笔记：打开笔记后点击 `Download`，下载当前 Markdown 文件。
11. 搜索笔记：在左侧搜索框输入关键词，结果会按匹配笔记展示；清空搜索框恢复目录树。

当前编辑模式只修改正文，不支持直接重命名或移动已有笔记。如需重命名或移动，可新建目标笔记后删除旧笔记，或直接在 vault 文件系统中调整。

## 文件与命名规则

新建笔记的文件名格式为：

```text
YYYY-MM-DD_标题.md
```

标题会经过文件名安全清理：

- 替换路径分隔符和 Windows 非法文件名字符。
- 移除控制字符。
- 折叠多余空白。
- 限制标题 stem 长度为 120 个字符。

上传文件会保留安全清理后的原文件名，仅允许 Markdown 后缀。

图片附件默认保存到当前目录或当前笔记目录下的 `_attachments/<note-stem>/`，Markdown 文件中保存相对路径。预览时前端会按当前笔记路径解析 `![](...)` 和 Obsidian `![[...]]` 图片引用，并转换为 `/api/notes/media` 读取；导入后的 `_attachments/<note-stem>/...` 相对链接、中文路径、空格和括号文件名都应正常展示。上传 Markdown、批量导入 Markdown 或导入 Office 时，如果正文里已有 `data:image/...;base64` 图片，系统会先解码为附件并把正文链接改写为相对附件路径。

批量 ZIP 导入会保留 ZIP 内 Markdown/Office 文件的目录结构。例如 `runbooks/a.md` 导入到目标目录 `导入` 后会写入 `导入/runbooks/a.md`。ZIP 中被 Markdown 引用的本地图片不会作为独立笔记导入，而是复制到对应笔记目录下的 `_attachments/<note-stem>/`。同名附件会自动追加 `-1`、`-2` 后缀，避免覆盖。旧版 Windows/压缩工具生成的 GBK/GB18030 中文文件名会在导入时尝试恢复，避免文件名乱码。

推荐 ZIP 结构：

```text
runbooks/
  login.md
  img/
    login.png
reports/
  weekly.docx
```

`login.md` 中可以写 `![登录截图](./img/login.png)`。不要把所有内容额外包一层没有意义的根目录，除非希望导入后也保留这层目录；不要包含隐藏目录、`__MACOSX`、绝对路径或 `..` 路径。

如果从 Obsidian 导出，也可以使用附件目录和 wiki 图片链接：

```text
runbooks/
  login.md
  附件/
    login.png
```

`login.md` 中可以写 `![[附件/login.png]]`。导入后图片会从原 `附件/` 目录复制到 `runbooks/_attachments/login/login.png`，Markdown 链接会改写为标准 `![](...)`，以便 WebUI 预览稳定展示。

## API 列表

### `GET /api/notes/tree`

返回 vault 状态、目录树、扁平笔记列表和默认分类。

响应字段：

- `root`：当前 vault 根目录的绝对路径。
- `exists`：vault 目录是否存在。
- `tree`：目录树节点。
- `notes`：所有 Markdown 笔记的扁平列表。
- `default_categories`：默认分类建议。

### `GET /api/notes?dir=<dir>`

列出指定目录下的 Markdown 笔记。`dir` 为空或 `.` 时表示 vault 根目录。

### `POST /api/notes`

新建笔记。

请求 JSON：

```json
{
  "title": "登录失败排查",
  "category": "01-故障知识库",
  "content": "# 登录失败排查\n"
}
```

### `GET /api/notes/content?path=<path>`

读取单篇笔记内容。`path` 是相对 vault 根目录的 Markdown 路径。

### `PUT /api/notes/content`

更新单篇笔记正文。

请求 JSON：

```json
{
  "path": "01-故障知识库/2026-05-28_登录失败排查.md",
  "content": "# 更新后的内容\n"
}
```

### `POST /api/notes/content`

兼容更新接口，行为与 `PUT /api/notes/content` 一致。

### `POST /api/notes/delete`

删除单篇笔记。

请求 JSON：

```json
{
  "path": "01-故障知识库/2026-05-28_登录失败排查.md"
}
```

### `POST /api/notes/upload`

上传 Markdown 文件。请求类型为 `multipart/form-data`。如果 Markdown 正文包含 `![...](data:image/...;base64,...)`、带 `charset` 等参数的 data URI、折行 base64 或缺少 padding 的 base64 图片，上传时会解码到 `_attachments/<note-stem>/` 并重写正文链接。

Knowledge Markdown/Office/ZIP 导入默认允许最大 500MB，可通过 `HERMES_WEBUI_KNOWLEDGE_IMPORT_MAX_MB` 覆盖；编辑器图片附件上传仍使用通用 `HERMES_WEBUI_MAX_UPLOAD_MB` 限制。

字段：

- `file`：上传文件。
- `target_dir`：目标目录，可为空。

### `POST /api/notes/import`

导入 Office 文档为 Markdown。请求类型为 `multipart/form-data`。

字段：

- `file`：`.docx`、`.xlsx` 或 `.pptx` 文件。
- `target_dir`：目标目录，可为空。
- `title`：可选标题；为空时使用源文件名。

该接口依赖可选 `markitdown` 包。未安装时返回明确错误，不影响普通 Markdown CRUD。对于 `.docx`、`.xlsx`、`.pptx` 中的 OOXML 内嵌图片，系统会从 `word/media/`、`xl/media/`、`ppt/media/` 提取图片，保存到 `_attachments/<note-stem>/`，并在 Markdown 末尾追加 `## 附件图片` 段落。如果转换器已经把图片写成 `![...](data:image/...;base64,...)`、`![...](<data:image/...;base64,...>)` 或带 `charset` 等参数、空格、换行的 data URI，导入时会先把 data URI 解码成附件文件并重写正文链接，不会把 base64 图片保留在 Markdown 中。

### `POST /api/notes/import/batch`

批量导入 ZIP。请求类型为 `multipart/form-data`。

字段：

- `archive`：ZIP 文件。兼容字段名 `file`。
- `target_dir`：目标目录，可为空。

支持内容：

- `.md`、`.markdown`：导入为 Markdown 笔记；正文中的 `data:image/...;base64` 图片会落盘为附件并改写链接。
- `.docx`、`.xlsx`、`.pptx`：通过 `markitdown` 转为 Markdown，并提取内嵌图片；转换器输出的 `data:image/...;base64` 图片会落盘为附件并改写链接。
- `.png`、`.jpg`、`.jpeg`、`.gif`、`.webp`：不单独导入；仅在被 Markdown 本地图片链接引用时复制为附件。

Markdown 图片处理规则：

- 识别 `![alt](./relative/image.png)` 这类相对路径图片。
- 识别 Obsidian wiki 图片链接，例如 `![[附件/image.png]]` 或 `![[image.png|说明]]`。
- 忽略 `http://`、`https://`、`data:`、`api/notes/media?...` 等外部或已路由链接。
- 图片路径按源 Markdown 文件在 ZIP 内的位置解析。
- 如果只写裸文件名或使用常见附件目录名，会额外尝试 `_attachments/`、`attachments/`、`assets/`、`attach/`、`附件/`、`图片/`、`images/`、`img/` 等目录。
- 找到图片后复制到 `_attachments/<note-stem>/`，并把 Markdown 链接改写为相对附件路径。
- 找不到本地图片时，该 Markdown 文件导入失败，失败项 `stage` 为 `copy_assets`，不会写入半成品笔记。

响应示例：

```json
{
  "ok": false,
  "imported": [
    {"source": "runbooks/a.md", "path": "导入/runbooks/a.md", "assets": 2}
  ],
  "failed": [
    {"source": "runbooks/b.md", "stage": "copy_assets", "error": "本地图片未找到：./img/missing.png"}
  ],
  "total": 2,
  "success_count": 1,
  "failure_count": 1,
  "skipped_count": 3
}
```

`ok` 表示本次批量导入是否完全成功。即使 `ok` 为 `false`，成功的文件也已经写入 vault；失败文件会保留 `source`、`stage`、`error`，便于用户修正源 ZIP 后重试。

### `POST /api/notes/assets`

上传图片附件并返回 Markdown 插入语法。请求类型为 `multipart/form-data`。

字段：

- `file`：图片文件，支持 `.png`、`.jpg`、`.jpeg`、`.gif`、`.webp`。
- `note_path`：当前笔记路径，编辑已有笔记时使用。
- `target_dir`：目标目录，新建未保存笔记时使用。

响应包含：

- `path`：附件相对 vault 根目录路径。
- `relative_path`：相对当前笔记目录的路径。
- `markdown`：可插入编辑器的 `![](...)` 语法。
- `url`：预览用媒体 URL。

### `GET /api/notes/media?path=<path>`

读取图片附件。只允许图片后缀，路径仍受 vault 沙箱保护。

### `GET /api/notes/download?path=<path>`

下载单篇 Markdown 笔记。

响应头包含：

- `Content-Type: text/markdown; charset=utf-8`
- `Content-Disposition`：同时提供 ASCII fallback 和 UTF-8 文件名。

### `GET /api/notes/search?q=<keyword>`

搜索标题和正文，返回最多 100 条结果。搜索时单文件正文读取上限为 512 KiB，超过上限的文件仍可按标题匹配。

### `POST /api/notes/directories`

新建目录。

请求 JSON：

```json
{
  "parent": "01-故障知识库",
  "name": "数据库"
}
```

`parent` 为空字符串或 `.` 时在 vault 根目录下创建一级目录。

### `PUT /api/notes/directories`

重命名目录，或预留用于移动目录。

请求 JSON：

```json
{
  "path": "01-故障知识库/数据库",
  "name": "MySQL"
}
```

### `DELETE /api/notes/directories`

删除目录。默认只允许删除空目录；非空目录需要显式 `recursive: true`。

请求 JSON：

```json
{
  "path": "01-故障知识库/MySQL",
  "recursive": false
}
```

### 兼容路径风格接口

后端也兼容以下路径风格接口，便于未来适配不同前端或代理：

- `GET /api/notes/<path>`
- `PUT /api/notes/<path>`
- `DELETE /api/notes/<path>`
- `GET /api/notes/download/<path>`

路径中的中文和特殊字符需要 URL 编码。

## 安全策略

模块只暴露 vault 根目录下的 Markdown 内容，核心限制如下：

- 禁止绝对路径。
- 禁止 `..` 路径穿越。
- 禁止 NUL 字节。
- 禁止访问隐藏路径和隐藏目录。
- 禁止访问 `.obsidian` 目录。
- 只允许 `.md` 和 `.markdown` 笔记。
- 附件目录 `_attachments` 不展示在知识树中。
- 媒体读取接口只允许图片后缀。
- Office 导入依赖可选转换器，失败时不会写入半成品笔记。
- 下载响应使用 `no-store`，并附加 WebUI 统一安全响应头。
- Markdown/Office/ZIP 导入大小遵循 `api.config.KNOWLEDGE_IMPORT_MAX_BYTES`（默认 500MB）。
- 编辑器附件上传大小遵循 `api.config.MAX_UPLOAD_BYTES`。

这些规则在后端统一执行，前端校验只作为用户体验补充。

## 已知限制

- 当前 MVP 不调用 Obsidian 应用，也不读取 Obsidian 插件配置。
- 不支持双向链接图谱、标签索引、反向链接或 Obsidian Canvas。
- 编辑已有笔记时不支持前端内重命名和移动目录。
- 搜索是简单大小写折叠匹配，不是分词索引。
- 删除单篇 Markdown 文件时不自动清理空目录。
- 并发编辑没有版本冲突检测，后保存的内容会覆盖前一次保存。
- Office 图片保留能力取决于可选转换器实际输出；当前接口为适配层，不捆绑重型 Office 转换依赖。

## 后续规划

可按需求逐步扩展：

- 增加重命名和移动笔记能力。
- 增加目录移动、目录拖拽排序和空目录自动清理。
- 增加标签、反向链接和最近修改视图。
- 增加基于 mtime 或内容 hash 的编辑冲突检测。
- 抽象 vault adapter，未来可接入 Obsidian Local REST API、远程同步或索引服务。
- 为大规模 vault 增加增量索引，避免每次搜索遍历文件系统。
