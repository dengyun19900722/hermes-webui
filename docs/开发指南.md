## 第一章：代码架构深度解读

### 1.1 技术栈概览

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| 后端 | Python 3.12 + stdlib | 无第三方 Web 框架，`ThreadingHTTPServer` |

### 1.4 请求/响应流程

```
浏览器                        WebUI Server                    Hermes Agent
  │                               │                                │
  │  POST /api/chat/start         │                                │
  │  {session_id, model, msg}   │                                │
  │────────────────────────────►│                                │
  │                              │  创建 STREAMS[stream_id]=Queue   │
  │                              │  启动 daemon 线程                │
  │                              │  _run_agent_streaming()         │
  │                              │───────────────────────────────►│
  │                              │                                │ AIAgent.run()
  │                              │◄───────────────────────────────│
  │                              │  put(token:{text})              │
  │                              │◄───────────────────────────────│
  │                              │  put(tool:{name,preview})       │
  │  ◄───────────────────────────│                                │
  │  event: token {text}         │                                │
  │────────────────────────────►│                                │
  │  GET /api/chat/stream        │                                │
  │  ?stream_id=xxx             │                                │
  │                              │◄─ queue.get() 阻塞              │
  │  ◄───────────────────────────│                                │
  │  event: tool {name}          │                                │
  │                              │                                │
  │  ◄───────────────────────────│                                │
  │  event: done {session}       │                                │
```

### 1.5 Session 模型

```python
class Session:
    session_id    # hex 12位，uuid4().hex[:12]
    title         # 自动从首条用户消息截取前64字符
    workspace     # 绝对路径
    model         # 模型 ID（如 "anthropic/claude-sonnet-4.6"）
    messages      # OpenAI-format 消息列表
    created_at    # Unix timestamp
    updated_at    # 每次 save() 更新
    pinned        # 是否置顶
    archived      # 是否归档
    project_id    # 所属项目 FK
    tool_calls    # 工具调用记录列表
    input_tokens/output_tokens/estimated_cost  # 用量统计
```

**内存缓存**：`SESSIONS = {session_id: Session}`，每次 save 全量写 JSON 文件。

### 1.6 SSE 事件类型

| 事件 | data 格式 | 触发时机 |
|------|----------|---------|
| `token` | `{"text": "..."}` | 每个 LLM token 输出 |
| `tool` | `{"name": "...", "preview": "..."}` | 工具调用开始 |
| `tool_result` | `{"name": "...", "result": "..."}` | 工具调用完成 |
| `approval` | `{"command": "...", "description": "..."}` | 危险命令待审批 |
| `done` | `{"session": {...}, "usage": {...}}` | agent 正常结束 |
| `error` | `{"message": "...", "trace": "..."}` | agent 异常 |
| `compressed` | `{"message": "..."}` | 上下文压缩触发 |
| `pending_steer_leftover` | `{"session_id": "...", "text": "..."}` | steer 残留 |

#### 3.1.1 需求分析

**需求背景**

ZK 运维智能体面向企业内网业务系统，审计合规是刚性需求。所有通过 Hermes WebUI 与 agent 进行的交互，都必须留下完整、不可篡改的操作痕迹，以满足：
- 监管合规要求（操作可追溯）
- 安全事件溯源（谁在什么时间做了什么）
- 运维审计需求（问答内容永久存档，支持事后复盘）

**现状调研**

| 审计维度 | 现状 | 差距 |
|---------|------|------|
| 访问时间 | `log_request()` 仅输出结构化 JSON 到 stdout（含 method/path/status/ms），无持久化 | ❌ 仅内存/临时，重启丢失 |
| 时间戳 | 同上，仅在请求日志中出现 | ❌ 无对话级别时间戳 |
| 客户端 IP | `handler.client_address[0]` 仅在 SSE/gateway 相关路由中使用，未纳入审计 | ⚠️ 部分获取，未系统化 |
| 会话 ID | `session_id` 存储在 Session JSON 文件中，随对话持久化 | ✅ 已有 |
| 交互角色 | `role: user/assistant/tool` 存储在 `messages[]` 中 | ✅ 已有 |
| 问答内容 | `messages[]` 中存储，但格式为 OpenAI message 格式，非结构化审计字段 | ⚠️ 格式耦合 |
| 浏览器 UA | `handler.headers.get("User-Agent")` 任何路由均可获取，但未记录 | ❌ 未采集 |
| 操作类型 | `self.path`（API 路径）已有，但未结构化标注"读/写/删/执行" | ⚠️ 粗粒度 |
| 审计存储 | 暂无独立审计表，仅通过 stdout 打印 | ❌ 不满足永久留痕 |
| 审计查询 | 无 Web 界面 | ❌ 全靠人工 grep stdout |
| 导出能力 | 无 | ❌ 无 Excel/CSV |

**核心差距总结**

现有架构仅有请求日志（stdout），无独立审计日志体系。最接近的是 `streaming.py` 中 `put('done', ...)` 事件携带的 session 数据，但那是业务数据而非审计数据。

#### 3.1.2 架构切入点分析

**A. 请求拦截层（最佳位置）**

`server.py` 的 `Handler` 类是所有请求必经之地：

```python
# server.py do_GET / do_POST
# 每个请求都经过这里，可统一注入审计字段
self._req_t0 = time.time()
# → 可记录：client_ip, user_agent, session_id(从cookie/body解析), path, method, status, duration
```

审计字段来源：
- `handler.client_address[0]` — 客户端 IP（已有部分使用）
- `handler.headers.get("User-Agent")` — UA（未使用）
- `handler.headers.get("Cookie")` — 可解析 session_id
- `time.time()` — 时间戳
- `self.command` — GET/POST
- `self.path` — 路由路径
- `parsed._qstring` — 查询参数（脱敏后）

**B. SSE 流式层（对话内容采集）**

`streaming.py` 的 `_run_agent_streaming()` 是采集对话内容的关键：

```python
# streaming.py 中每个 token/turn 均可采集
put('token', {'text': text})          # token 级别（太细，一般不看）
put('tool', {'name': name})           # 工具调用
# done 事件有完整 session，包含 messages[]
```

**C. 现有 Session 模型审计字段缺失**

`api/models.py` Session 类：
```python
self.messages  # 有 role/content/timestamp，但非审计专用
# 缺失：client_ip, user_agent, operation_type(登录/提问/上传/...)
```

**D. config.py 审计配置发现**

`api/config.py` 中可添加审计相关配置：
```python
AUDIT_DIR         # 审计日志目录
AUDIT_ENABLED     # 审计开关
AUDIT_IP_ANONYMIZE # IP 脱敏
```

**A1 审计核心** ✅

`api/audit.py` 独立模块，13 个公开 API：

| API | 签名 | 说明 |
|-----|------|------|
| `write` | `(entry: dict) -> None` | 异步缓冲写入（< 1ms延迟） |
| `flush` | `() -> None` | 同步 drain buffer |
| `search` | `(category, session_id, client_ip, keyword, since, until, limit, offset)` | 条件搜索 |
| `count` | `(category, since, until) -> int` | 计数 |
| `export_csv` | `(...) -> io.StringIO` | CSV 导出（UTF-8 BOM） |
| `rotate_old_logs` | `(age_days=7) -> dict` | gzip 压缩老日志 |
| `cleanup` | `(days=None) -> dict` | 删除超期压缩日志 |

关键设计：
- 内存缓冲 + 后台 flush 线程（每5s或32条触发），`write()` 极低延迟
- `_entry_buffer` 线程安全，`fcntl.LOCK_EX` 保护文件写入
- `_ensure_audit_dir()` 惰性初始化，不创建审计目录直到首次写入
- IP 匿名化（IPv4 末段清零）+ 敏感字段脱敏（正则 `***REDACTED***`）
- 日期边界：bare date `since`=start-of-day，`until`=end-of-day（包含）
- Fire-and-forget：`write()` 异常被捕获，只记日志不抛给调用方
