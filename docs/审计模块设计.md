# Hermes WebUI 审计模块详细设计

> 本文档记录 Hermes WebUI 安全与合规模块（REG-07）的完整设计与实现。
> 开发过程详见 `开发指南.md` 第一章REG-07 章节。

---

## 一、模块概述

**模块名称**：`api/audit`
**核心职责**：对所有 HTTP 请求做结构化审计记录，支持查询、导出、日志轮转与自动清理。
**依赖文件**：`api/audit.py`（主模块）、`tests/test_audit_logger.py`（62个测试用例）

## 二、技术规格

### 2.1 存储格式

| 属性 | 值 |
|------|-----|
| 存储格式 | JSON Lines（`.jsonl`），每行一个 JSON 对象 |
| 目录 | `HERMES_WEBUI_AUDIT_DIR`（默认 `STATE_DIR/audit-logs`） |
| 文件命名 | `audit-YYYY-MM-DD.jsonl`（按天分片） |
| 压缩格式 | Gzip（`.jsonl.gz`），仅老日志压缩后保存 |
| 编码 | UTF-8，无 BOM |

### 2.2 Entry 字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | UUID4，由 `write()` 自动注入 |
| `ts` | string | ISO-8601 UTC 时间戳，`YYYY-MM-DDTHH:MM:SS+00:00` |
| `category` | string | 请求分类：`request`/`auth`/`chat`/`session`/`admin`/`log_context` |
| `session_id` | string | 关联会话 ID（无则为空字符串） |
| `operation` | string | 操作描述（如路由路径或操作名） |
| `method` | string | HTTP 方法 |
| `path` | string | 请求路径 |
| `status` | int | HTTP 状态码 |
| `duration_ms` | int | 请求耗时（毫秒） |
| `client_ip` | string | 客户端 IP（可配置匿名化；采集优先级为 `X-Forwarded-For` 第一段、`X-Real-IP`、socket 客户端地址） |
| `user_agent` | string | User-Agent |
| `question` | string | 用户提问（前512字符，敏感字段已脱敏） |
| `answer` | string | Agent 回答摘要（同上） |
| `tool_calls` | list | 工具调用列表 |
| `login_success` | bool | 登录是否成功 |
| `login_reason` | string | 登录失败原因 |
| `source` | string | 日志上下文来源 ID（`category=log_context` 时） |
| `host_ip` | string | 日志上下文目标主机 IP（`category=log_context` 时） |
| `account` | string | 日志上下文目标只读账号（`category=log_context` 时） |
| `line` | int | 日志命中行号（`category=log_context` 时） |

### 2.3 配置文件（`api/config.py`）

> **多实例部署**：直接编辑 `api/config.py` 中的审计配置区段，每套实例使用不同目录即可区分审计数据。

|| 配置项 | 默认值 | 说明 |
|------|--------|--------|------|
| `AUDIT_DIR` | `/data/audit-logs` | 审计日志存储目录 |
| `AUDIT_IP_ANONYMIZE` | `False` | `True`: IPv4 末段清零（`192.168.1.99` → `192.168.1.0`） |
| `AUDIT_RETENTION_DAYS` | `90` | 自动清理阈值（`0`=禁用） |
| `AUDIT_ENABLED`（audit.py 内） | `True` | 审计总开关 |

## 三、架构设计

### 3.1 异步写入模型

```
write(entry)  ──buffer──►  [_entry_buffer]  ──(每5s或32条触发)──►  flush()
                                                              │
                                                         _flush_buffer()
                                                              │
                                                    ┌────────┴────────┐
                                                    │  open(path, "a")│
                                                    │  fcntl.LOCK_EX  │
                                                    │  json.dumps()   │
                                                    │  f.close()      │
                                                    └─────────────────┘
```

- **`write()`**：极低延迟（< 1ms），只做内存 buffer append，不落盘
- **`flush()`**：同步 drain buffer，server shutdown 时调用
- **后台 flush 线程**：每 5s 检查 buffer size > 0 时自动触发（daemon thread）
- **Fire-and-forget**：`write()` 任何异常被捕获并记录，不影响请求处理路径

### 3.2 内部状态（模块级变量）

```
 AUDIT_ENABLED       bool          ← 运行时可写（from config + env）
 AUDIT_DIR           Path          ← 运行时可写（同上）
 AUDIT_IP_ANONYMIZE  bool          ← 运行时可写（同上）
 AUDIT_RETENTION_DAYS int          ← 运行时可写（同上）

 _entry_buffer       list[dict]    ← 内存缓冲（线程安全由 _buffer_lock 保护）
 _buffer_lock        Lock
 _shutdown_event     Event
 _flush_thread       Thread | None
 _audit_dir          Path | None   ← 惰性计算结果（_ensure_audit_dir() 的缓存）
```

### 3.3 IP 匿名化

HTTP 请求审计和 chat 审计都会写入顶层 `client_ip` 字段。反向代理部署下优先读取 `X-Forwarded-For` 第一段，其次读取 `X-Real-IP`；未提供代理头时回退到 `handler.client_address[0]`。

日志上下文查看也会写入 `category=log_context` 审计记录，字段包含
`source`、`host_ip`、`account`、`path`、`line`、`before`、`after`、
`client_ip`、`session_id` 和 `outcome`，不记录密码或密码环境变量值。
失败场景会额外记录 `error_code`，例如 `source_not_found`、
`path_not_allowed`、`login_failed`、`timeout`。

```
RE_IPV4_SEG = r"\.\d+$"

_anonymize_ip("192.168.1.99")
  └─ RE_IPV4_SEG.sub(".0", ip) → "192.168.1.0"
```

仅对 IPv4 生效，IPv6 地址保持不变。

### 3.4 敏感字段脱敏

使用正则检测 entry 所有字符串字段中的 `key|secret|password|token|auth|bearer|credential` 等关键词及其值，替换为 `***REDACTED***`。

## 四、API 接口

### 4.1 `write(entry: dict) -> None`

将一个审计条目压入缓冲区（异步写入）。

**参数**：
- `entry: dict` — 审计条目，必含 `category`，可选含 `session_id`/`operation`/`method`/`path`/`status`/`duration_ms`/`client_ip`/`user_agent` 等字段
- `write()` 自动补充 `id`（UUID4）和 `ts`（UTC now）字段

**行为**：
- 若 `len(_entry_buffer) >= 32` → 立即触发同步 flush
- 后台 flush 线程每 5s 检查一次
- 异常被捕获，只记录日志，不抛给调用方

### 4.2 `flush() -> None`

同步将所有缓冲条目写入磁盘。

**调用场景**：
- server shutdown 时（在 `ThreadingHTTPServer` shutdown hook 中）
- 测试用例中验证写入结果后
- `write()` 内部 buffer 满时自动触发

### 4.3 `search(category, session_id, client_ip, keyword, since, until, limit, offset) -> list[dict]`

按条件搜索审计日志。

**日期语义**：
- `since="2026-05-01"` → 5月1日 00:00:00 UTC（包含）
- `until="2026-05-01"` → 5月1日 23:59:59.999999 UTC（包含）
- 支持 ISO-8601 和 bare date 两种格式

**返回**：按 `ts` 降序（最新优先），最多 `limit` 条，支持 `offset` 分页

### 4.4 `count(category, since, until) -> int`

返回符合条件的条目总数（用于 UI 显示总条数）。

### 4.5 `export_csv(category, session_id, since, until, keyword) -> io.StringIO`

导出为 CSV（UTF-8 BOM），字段包括：id, ts, category, session_id, operation, client_ip, user_agent, method, path, status, duration_ms, question, answer, tool_calls, login_success, login_reason。

**工具调用字段**：序列化为分号连接的字符串。

### 4.6 `rotate_old_logs(age_days=7) -> dict`

将 `age_days` 天之前的 `.jsonl` 文件 gzip 压缩为 `.jsonl.gz`（原地替换）。

**返回**：`{"rotated": N, "skipped": M, "errors": K, "error_detail": "..."}`

**保护逻辑**：
- 已有同名 `.gz` → 跳过
- 压缩失败 → 删除临时 `.gz`，保留原始文件
- 压缩后验证 gzip 完整性

### 4.7 `cleanup(days=90) -> dict`

删除超过 `days` 天的压缩日志（`.jsonl.gz`）。

**返回**：`{"deleted": N, "skipped": M, "errors": K, "detail": "..."}`

**策略**：
- 仅删除 `.jsonl.gz`（不删未压缩的活跃数据）
- `days=0` → 无操作（retention disabled）
- `days=None` → 读取 `AUDIT_RETENTION_DAYS` 配置

## 七、server.py 集成

### 7.1 IP 捕获

```
do_GET(handler):
    handler._client_ip = resolve_ip(handler)   # X-Forwarded-For 或 client_address
    super().do_GET(handler)

do_POST(handler):
    handler._client_ip = resolve_ip(handler)
    super().do_POST(handler)
```

### 7.2 审计写入

覆盖 `log_request()` 方法，在标准日志后写审计条目：

```
log_request(handler):
    entry = {
        "category":    "request",
        "session_id":  handler.session_id or "",
        "operation":   handler.path,
        "method":      handler.command,
        "path":        handler.path,
        "status":      self.send_response  # via handler._status_code
        "duration_ms": handler._request_time_ms,
        "client_ip":   handler._client_ip,
        "user_agent":  handler.headers.get("User-Agent", ""),
    }
    audit.write(entry)
    audit.flush()  # if not shutting_down
```

### 7.3 Shutdown Hook

server shutdown 时调用 `audit.flush()` 确保所有缓冲条目落盘。

## 九、关键实现细节

### 9.1 `importlib.reload` 兼容性

`api/audit.py` 从 `api.config` 导入配置常量，直接引用 `config.py` 中定义的字面值，无需环境变量解析。

测试中通过直接赋值模块属性（如 `audit.AUDIT_DIR = new_path`）覆盖，不依赖 reload。

### 9.2 日期解析

Bare date（如 `"2026-05-01"`）用 `strptime` + `timedelta` 处理，不走 `fromisoformat`（否则 bare date 会因缺少时间部分被拒绝）。

```
since="2026-05-01"  → datetime(2026,5,1, 0,0,0, tzinfo=utc)
until="2026-05-01"  → datetime(2026,5,1,23,59,59,999999, tzinfo=utc)
```

### 9.3 文件锁

`_flush_buffer()` 对写入文件加 `fcntl.LOCK_EX`（排他锁），读操作不加锁（jsonl 可并发读）。

### 9.4 `_ensure_audit_dir()` 惰性初始化

`_audit_dir` 是惰性计算结果，只在第一次调用时创建目录并缓存，避免审计禁用时也创建目录。
