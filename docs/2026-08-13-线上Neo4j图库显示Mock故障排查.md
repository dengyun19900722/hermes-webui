# 线上环境 Neo4j 图库显示 Mock 的故障排查与修复

> 本文档记录线上 `ops-hermes-webui` 容器内环境变量齐全但页面仍展示 Mock 的完整排查思路、根因与修复。适用于 Docker Compose 多容器编排下 WebUI 连接 Neo4j 的场景。

## 现象

- 进入容器执行 `env | grep NEO4J`，能看到 `NEO4J_URI` / `NEO4J_USER` / `NEO4J_PASSWORD` 等变量均已设置。
- 但 WebUI 的 Graph 页面右上角徽章仍显示 `Mock`，且提示 "Graph is empty"。
- 调用健康检查接口返回 `backend: mock`：

```json
{"ok": true, "data": {"backend": "mock", "ok": true, "detail": "sqlite at /workspace/.graph/graph.sqlite (thread-local)"}}
```

## 关键结论

**环境变量能 `env` 看到，不代表 web 进程实际拿到了它、更不代表能连上 Neo4j。** 页面显示 Mock 与容器里有没有 NEO4J 变量没有必然关系，真正的判据是后端 `get_store()` 的 health 检查是否通过。

## 后端 backend 选择逻辑（代码依据）

图库后端选择集中在 `api/graph.py` 的 `get_store()`：

- 单例懒加载，优先尝试 `Neo4jStore`，调用 `store.health()`。
- 仅当 `health().ok == True` 时才使用 Neo4j；否则打印日志 `"Graph store: MOCK ... — set NEO4J_PASSWORD to enable Neo4j backend"` 并降级为 `MockStore`（SQLite 持久化，数据落在 `DEFAULT_WORKSPACE/.graph/graph.sqlite`）。
- `api/graph_neo4j.py` 的 `Neo4jStore` 判定两点：
  1. `NEO4J_PASSWORD` 为空 / 未设置 → `detail: "not_configured"`，直接降级 Mock。
  2. 密码存在但连接失败（URI 不对、网络不通、认证失败）→ `detail: "neo4j unreachable: ..."`，同样降级 Mock。

前端 `static/graph_main.js` 通过 `GET /api/graph/health` 的 `h.backend` 字段决定徽章文字（`neo4j` → "Neo4j"，其余 → "Mock"）。因此只要后端走了 Mock 分支，前端必然显示 Mock。

## 根因

线上 `/opt/hermes/config/.env` 中 Neo4j 配置为：

```bash
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=neo4j123
NEO4J_HTTP=http://localhost:7474
```

而 WebUI 运行在 Docker 容器内，**容器内的 `localhost` 指向容器自身，而非宿主机**。`ops-hermes-webui` 容器自己并不是 Neo4j，所以 `bolt://localhost:7687` 连不到 Neo4j，`health()` 返回 `ok: false`，后端降级为 Mock。

## 排查步骤（通用思路）

无论具体环境如何，按以下三步定位：

1. **确认后端真实选择的 backend**（不要只看容器里 `env`）：
   ```bash
   docker exec ops-hermes-webui bash -lc \
     'curl -s http://127.0.0.1:8787/api/graph/health'
   ```
   - `backend: neo4j, ok: true` → 后端已连上，问题在前端/缓存。
   - `detail: "not_configured"` → web 进程没拿到 `NEO4J_PASSWORD`（查环境注入方式）。
   - `detail: "neo4j unreachable: ..."` → 拿到密码但连不上 Neo4j（看 detail 具体原因）。
   - `backend: mock` → 走了 Mock 分支，配合日志确认降级原因。

2. **看 web 进程真实运行环境**（`env` 命令只是你进去的 shell，不是 web 进程）：
   ```bash
   docker exec ops-hermes-webui bash -lc \
     'tr "\0" "\n" < /proc/1/environ | grep NEO4J'
   ```

3. **看启动日志里 Graph store 选了谁**（一行定案）：
   ```bash
   docker logs ops-hermes-webui 2>&1 | grep -E "Graph store|neo4j" | tail -5
   # 期望：Graph store: Neo4j (connected)
   ```

## 修复方案

### 方案 A：同 Compose 编排，用 service 名访问（推荐）

若 WebUI 与 Neo4j 在**同一个 `docker-compose.yml`** 中编排，二者处于同一默认 bridge 网络，应使用 **service 名** 而非 IP 或 localhost：

```bash
# /opt/hermes/config/.env
NEO4J_URI=bolt://<neo4j-service-name>:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=neo4j123
NEO4J_HTTP=http://<neo4j-service-name>:7474
```

将 `<neo4j-service-name>` 替换为 compose 中 Neo4j 服务的实际名字（可用 `docker ps` 查看）。同时确认两个 service 属于同一网络。

### 方案 B：两个容器不同 Compose / 手动启动，用宿主机 IP

若 Neo4j 不在 WebUI 的 compose 网络内，退回用宿主机 IP：

```bash
NEO4J_URI=bolt://8.130.174.85:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=neo4j123
NEO4J_HTTP=http://8.130.174.85:7474
```

需确认 Neo4j 端口映射到 `0.0.0.0`（而非仅 `127.0.0.1`），否则容器外连不到。用 `ss -tln | grep -E '7687|7474'` 检查监听地址。

### 方案 C：Neo4j 原生装在宿主机（非容器）

WebUI 容器内访问宿主机，Linux 可用 `host.docker.internal`（需给容器加 `--add-host=host.docker.internal:host-gateway`）或改用 host 网络模式（此时 `localhost` 才指向宿主机）。

### 补充建议：在 compose 的 `environment:` 块显式写死

compose 中 `environment:` 优先级高于 `env_file:`。若担心 `docker_init.bash` / `ctl.sh` 二次加载 `.env` 覆盖，可在 `ops-hermes-webui` 的 `environment:` 块显式写入：

```yaml
    environment:
      - NEO4J_URI=bolt://<neo4j-service-name>:7687
      - NEO4J_USER=neo4j
      - NEO4J_PASSWORD=neo4j123
      - NEO4J_HTTP=http://<neo4j-service-name>:7474
```

## 修改后重建与验证

```bash
cd /opt/hermes                 # docker-compose.yml 所在目录
docker compose up -d --force-recreate ops-hermes-webui
# 或 docker-compose up -d --force-recreate ops-hermes-webui

# 验证 1：后端日志
docker logs ops-hermes-webui 2>&1 | grep -E "Graph store|neo4j" | tail -5
# 期望：Graph store: Neo4j (connected)

# 验证 2：健康检查接口
curl -s http://127.0.0.1:8787/api/graph/health
# 期望：{"ok":true,"data":{"backend":"neo4j","ok":true,"detail":"connected"}}
```

页面再硬刷新一次（Cmd+Shift+R / Ctrl+Shift+R），右上角徽章应从 `Mock` 变为 `Neo4j`，"Graph is empty" 提示消失。

## 若仍连不上（网络层排查）

从容器内探测到 Neo4j service 名与端口：

```bash
# 容器内能否解析 service 名
docker exec ops-hermes-webui bash -c 'getent hosts <neo4j-service-name>'

# 容器内到 7687 (bolt) 端口是否可达
docker exec ops-hermes-webui bash -c \
  'cat < /dev/null > /dev/tcp/<neo4j-service-name>/7687 && echo "7687 OK" || echo "7687 FAIL"'
```

常见失败原因：

- 两个 service 不在同一网络（`getent hosts` 解析不到），检查 compose 的 `networks:` 定义。
- 云端安全组只放行 7474 未放行 7687（bolt 端口）。
- Neo4j 仅监听 `127.0.0.1`（需在 `neo4j.conf` 改为 `0.0.0.0`）。
